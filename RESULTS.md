## 4. Deviations, fixes and caveats (read this)


- **torch cu128 everywhere.** The official env scripts pin `torch==2.0.0+cu118`
  (DP), `torch==2.5.1` (GR00T) and `jax[cuda12]==0.5.0` (pi0.5) — none of which have
  `sm_120` (Blackwell) kernels. All three were replaced: torch → `2.7.0+cu128`,
  jax → **`0.6.2`** (the newest version that keeps `jax.experimental.layout.DeviceLocalLayout`,
  which `orbax-checkpoint==0.11.1` imports, *and* ships Blackwell kernels:
  ≥0.7 removed the API, 0.5.x has no sm_120 kernel).
- **Split server/client forced.** The repo's `eval_double_env.sh` scripts hard-code the
  simulator-side conda env as `dex2bench`; ours is `bench2dex`, so the three launchers
  `70_eval_dp.sh` / `72_eval_gr00t.sh` / `73_eval_pi05.sh` replicate that orchestration
  with the correct env names and our four Isaac fixes (local `libGLU.so.1`, the lab proxy,
  the `omni.kit.registry.nucleus` override for the unreachable CloudFront registry, and
  `CUDA_VISIBLE_DEVICES`).
- **GPU sharing.** Only GPU 2 was idle at the start (the other three are pinned by other
  users at ~100%). Everything here runs on GPU 2; at most 3 Isaac instances in parallel
  (≈13 GB each).
- **Run-to-run variance is real.** Two identical smoke runs (same seed, same checkpoint)
  gave `latched_stage_completion_rate` of 1.00 vs 0.25 for the same episode. Treat the
  per-cell numbers below as one sample; do not read a few percent as signal.
- **Data location.** All data/weights live on `/mnt/public/datasets/bench2dex/`
  (NFS, symlinked into `~/bench2dex/`); only the conda environments and code are on `/home`.

### ⛔ Known upstream blocker: GR00T N1.5 cannot be evaluated as released


The released `Bench2Dex/New_Policy` GR00T checkpoints for these tasks contain only
**4 files** (`config.json`, `model-0000{1,2}-of-00002.safetensors`,
`model.safetensors.index.json`) — verified against the ModelScope repo tree, and
`gr00t_n15/experiment_cfg` does not exist there at all.

But the code requires it:

* `policy/GR00T_n15/deploy_policy.py:127` → `_validate_local_checkpoint()` raises
  `FileNotFoundError` unless `<model_path>/experiment_cfg/metadata.json` is a file.
* `policy/GR00T_n15/src/gr00t/model/policy.py:110` → `_load_metadata(model_path/"experiment_cfg")`
  opens that JSON and validates the per-embodiment entry
  (`DatasetMetadata` = the state/action **normalization statistics** for the finetuned embodiment).

Those statistics are functionally required (they un-normalize the predicted actions), so
fabricating a `metadata.json` would produce silently wrong numbers — worse than not running.
Note the official `policy/GR00T_n15/eval_double_env.sh` auto-discovery would also pick this
same directory (it only checks `config.json` + `model-*.safetensors`), so the failure is
upstream, not a mistake in this run's arguments.

**To unblock GR00T you need one of:** the `experiment_cfg/metadata.json` for these
checkpoints from the authors; or regenerate it from the finetuning data
(`src/gr00t/utils/experiment.py` writes exactly this artifact; the finetuning corpus appears
to be the same `replay-generalization` HDF5s we already have); or re-finetune GR00T locally.
