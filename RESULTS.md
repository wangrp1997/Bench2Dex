## 4. Deviations, fixes and caveats (read this)


- **torch cu128 everywhere.** The official env scripts pin `torch==2.0.0+cu118` (DP),
  `torch==2.5.1` (GR00T) and `jax[cuda12]==0.5.0` (pi0.5) — none of which have `sm_120` (Blackwell)
  kernels. All three were replaced: torch → `2.7.0+cu128`, jax → **`0.6.2`** (newest version that
  both keeps `jax.experimental.layout.DeviceLocalLayout`, which `orbax-checkpoint==0.11.1` imports,
  and ships Blackwell kernels: ≥0.7 removed the API, 0.5.x has no sm_120 kernel).
- **Split server/client forced.** The repo's `eval_double_env.sh` scripts hard-code the
  simulator-side conda env as `dex2bench`; ours is `bench2dex`, so `70_eval_dp.sh`,
  `72_eval_gr00t.sh` and `73_eval_pi05.sh` replicate that orchestration with correct env names and
  our four Isaac fixes (local `libGLU.so.1`, the lab proxy, the `omni.kit.registry.nucleus` override
  for the unreachable CloudFront registry, and `CUDA_VISIBLE_DEVICES`).
- **Robot USD emits unresolved-reference warnings for every `*/visuals` prim**, e.g.
  `Unresolved reference prim path @.../multi_iiwa7_with_sharpa_physics.usd@</visuals/left_index_fingertip>`.
  The released `multi_iiwa7_with_sharpa_base.usd` (21 MB, holds the meshes) references visual prims
  that the 19 KB physics-only USD does not contain. It appears identically in the ACT and DP logs,
  and our asset download matches the documented file count (52,764 files) — so it is an upstream
  asset characteristic, not something this deployment broke. It does mean some wrist-camera views
  may lack hand geometry, which is one candidate explanation for the ACT/task-26 shortfall.
- **Run-to-run variance is real.** Two identical smoke runs (same seed, same checkpoint) gave
  `latched_stage_completion_rate` 1.00 vs 0.25 for the same episode. Treat each cell as one sample.
- **GPU sharing.** Only GPU 2 was idle (the other three are pinned by other users); everything here
  runs on GPU 2, at most 3 Isaac instances plus 3 policy servers at a time.
- **Data location.** All data/weights live on `/mnt/public/datasets/bench2dex/` (NFS, symlinked into
  `~/bench2dex/`); only the conda environments and code are on `/home`.

### GR00T N1.5: unblocked by reconstructing `experiment_cfg`


The released `Bench2Dex/New_Policy` GR00T checkpoints contain only **4 files** and no
`experiment_cfg/`, which `policy/GR00T_n15/deploy_policy.py:127` requires and
`src/gr00t/model/policy.py:110` reads for the embodiment's state/action **normalization
statistics**. Starting the server against them failed in 8 s with `FileNotFoundError`.

That artifact turns out to be a deterministic function of the training data, computed by the
repo itself: `gr00t_hdf5_dataset.Dex2BenchHDF5Dataset.__init__` calls `_compute_statistics()`
and assembles a `DatasetMetadata`, and `src/gr00t/experiment/runner.py:76-97` writes
`{tag: metadata}` to `<output_dir>/experiment_cfg/metadata.json` **inside `TrainRunner.__init__`**
-- before a single training step. (My earlier note in this report claiming the repo has no
statistics entry point was wrong; that was based only on `utils/experiment.py`, which is just
the checkpoint callback.)

`_deploy_logs/80_rebuild_gr00t_experiment_cfg.py` reproduces exactly the arguments
`policy/GR00T_n15/train.sh` passes -- hdf5-native, `Dex2BenchGR00TDataConfig`,
`--embodiment-tag new_embodiment`, the 4cam map (`stereo_left/right=cam_stereo_*`,
`*_wrist=cam_wrist_*`), `--hdf5-use-active-dof`, `--hdf5-truncate-at-homing`, and the scene
`description:` from `scenes/<TASK>.yaml` as the prompt -- and writes the same file:
task 26 = 100 episodes / 62,438 samples, task 32 = 100 / 55,900, task 73 = 100 / 81,514,
all with state_dim=54, action_dim=54 (Sharpa active DOF).

One real gap remained, and it was **mine, not upstream**: `flash-attn==2.8.2` is declared at
`policy/GR00T_n15/pyproject.toml:93` and imported unconditionally by the Eagle2 vision
backbone (`transformers_modules/eagle2_hg_model/radio_model.py` calls
`replace_vit_attn_with_flash_attn()` at import time), but my uv-based environment rebuild had
skipped it. Installed, after which the server loads:
`[GR00T] Active DOF: robot=multi_iiwa7_with_sharpa dims=54 (full=58)`,
`Set action denoising steps to 4`, `[policy-model-server] listening on 127.0.0.1:9200`, and
episode 1 of task 26 succeeded (`stable_success=True`, LSCR 1.00). A dependency audit now
shows 34/35 declared deps present; the only other one "missing" is `eva-decord`, which is
macOS-only.

**Caveat that matters when reading the GR00T numbers:** the statistics in `experiment_cfg`
are a **reconstruction** from the same `replay-generalization` HDF5s using the repo's own code
and the exact `train.sh` arguments -- not a file shipped by the authors. If their checkpoints
were finetuned on a different subset or config, the normalization would differ slightly and
the scores would shift. Compare against the paper's 17/12/10 with that in mind.
